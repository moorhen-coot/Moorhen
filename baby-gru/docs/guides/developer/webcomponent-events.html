Reacting to changes in Moorhen

Moorhen can notify your application when things change. There are two mechanisms: subscribe to any part of the store with subscribeToStore(), or use one of the ready-made callbacks (newAtomHoveredCallback(), newMoleculeChangedCallback(), files.newFilesLoadedCallback()).

Always unsubscribe. Every registration method in this guide returns a function that stops the subscription. Call it when you no longer need the callback (for example when a React component unmounts), otherwise it keeps firing for the lifetime of the page.

Prerequisite: the examples assume you already hold a moorhenInstance (see Setting up the WebComponent or Using the WebComponent in React).

1. Subscribe to store changes

subscribeToStore(selector, callback) watches any value in Moorhen’s store. The selector picks the value, and the callback runs whenever that value changes: 

const unsubscribe = moorhenInstance.subscribeToStore(
    (state) => state.molecules.moleculeList.length,
    (count) => {
        console.log(`${count} molecule(s) loaded`);
    },
);

// Later, to stop listening:
unsubscribe();

It does not fire immediately. The callback only runs when the selected value changes, so read the current value yourself for the initial state. Two easy ways are moorhenInstance.store.getState() and the convenience methods getMoleculeList() / getMapList().

The selector receives the whole store state (RootState), so any slice can be watched. Changes are compared with !==, which works well with Redux Toolkit’s immutable updates: make sure the selector returns a value that is stable when nothing changed.

In React you will usually reach for the useMoorhenSelector() hook instead, which wraps this and handles the subscription for you.

2. Atom hover

newAtomHoveredCallback(callback) fires whenever the pointer hovers over a real atom in the 3D view: 

const stopHover = moorhenInstance.newAtomHoveredCallback(
    (moleculeId, residueNumber, atomName) => {
        const molecule = moorhenInstance.getMolecule(moleculeId);
        console.log(
            `${atomName} in residue ${residueNumber} of ${molecule?.name ?? moleculeId}`,
        );
    },
);

// Later, to stop listening:
stopHover();

The callback gives you the molecule’s unique ID (use getMolecule() to get the molecule itself), the residue number and the atom name. It only fires once the hovered atom is a real atom, so you do not have to filter empty hover events.

3. Molecule changed

newMoleculeChangedCallback(callback, moleculeUid?) fires when a molecule is created, added, deleted, modified or refined: 

const stopChanges = moorhenInstance.newMoleculeChangedCallback(
    (moleculeId, action, cid) => {
        console.log(`Molecule ${moleculeId}: ${action}${cid ? ` (${cid})` : ""}`);
    },
);

// Later, to stop listening:
stopChanges();
  • action is one of "new", "add", "delete", "modify" or "refine" (moleculeChangeAction).
  • cid is the CID of the changed region, when relevant.
  • Pass a molecule unique ID as the second argument to only receive changes for that molecule.

If you change a molecule through your own code and want registered callbacks to know, fire the change yourself with triggerMoleculeChanged(): 

moorhenInstance.triggerMoleculeChanged(moleculeUid, "modify", cid);

4. Files loaded

The files group has its own callback, moorhenInstance.files.newFilesLoadedCallback(callback), which fires once per file that finishes loading: 

const stopFiles = moorhenInstance.files.newFilesLoadedCallback((file, origin) => {
    console.log(`Loaded ${file.fileName} (${file.type}) as ${file.uniqueID} from "${origin}"`);
});

// Later, to stop listening:
stopFiles();

file is a LoadFilesResult, the same shape returned by loadFiles(). The second argument is the optional origin label you pass to loadFiles(), which is handy when several parts of your app load files and you want to tell them apart: 

moorhenInstance.files.loadFiles(
    ["https://www.ebi.ac.uk/pdbe/entry-files/1bxn.cif"],
    "my-importer",
);

5. Unsubscribe when you are done

In a long-lived page, and especially in a single-page app, unsubscribe when the code that registered the callback is torn down. In React, return the unsubscribe functions from the effect: 

useEffect(() => {
    const instance = moorhenInstanceRef.current;
    if (!instance) {
        return;
    }

    const stopHover = instance.newAtomHoveredCallback((moleculeId, residueNumber, atomName) => {
        console.log(`${atomName} in residue ${residueNumber} of ${moleculeId}`);
    });

    const stopChanges = instance.newMoleculeChangedCallback((moleculeId, action) => {
        console.log(`Molecule ${moleculeId}: ${action}`);
    });

    return () => {
        stopHover();
        stopChanges();
    };
}, [moorhenInstanceRef]);

subscribeToStore() returns an unsubscribe function in the same way, and the useMoorhenSelector() hook manages its own subscription and cleanup.

Element events

One thing is not on the instance: the element dispatches a moorhenReady CustomEvent on window once it has mounted. That is covered in The Moorhen WebComponent and Setting up the WebComponent.

API reference

  • subscribeToStore() — subscribe to any store value.
  • newAtomHoveredCallback(), newMoleculeChangedCallback(), triggerMoleculeChanged().
  • files.newFilesLoadedCallback() — file-loading notifications.
  • RootState, moleculeChangeAction, LoadFilesResult.
