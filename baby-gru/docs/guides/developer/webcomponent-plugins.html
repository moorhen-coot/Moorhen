Adding your own tools to Moorhen

A plugin is code in your page that adds tools to Moorhen: a modal or a side panel of its own, opened from Moorhen’s menus, with controls that look like Moorhen’s and act on the structures and maps loaded in it. You do not change Moorhen’s code; three pieces make this work together:

  • Slots: your UI is ordinary HTML in your page, placed inside <moorhen-web-component> with a slot attribute (see Custom HTML slots).
  • UI extensions: moorhenInstance.uiExtensions registers a modal or side panel whose content is one of those slots.
  • Moorhen UI elements: <moorhen-button>, <moorhen-toggle>, <moorhen-molecule-select>… custom elements that render Moorhen’s own controls inside your slotted HTML, with Moorhen’s look and live access to its state.

This tutorial builds a small plugin step by step: a modal with a button, then view controls that stay in sync with Moorhen, then molecule and chain pickers, and finally the same plugin packaged as one React component that only loads its tools when the user first opens it.

Prerequisite: the examples assume you can already put Moorhen in a page and get its moorhenInstance (see Setting up the WebComponent or Using the WebComponent in React), and that you have read Adding custom menus and Custom HTML slots. Everything here comes from moorhen/web-component; no other package is needed.

1. A modal from a slot

Write the modal’s content as a child of the web component, with a slot name of your choice: 

<moorhen-web-component id="moorhen-1" width="1000" height="800">
    <div slot="my-plugin-body">
        <p>Hello from my plugin.</p>
        <moorhen-button id="my-plugin-load" icon="MatSymAdd" label="Load my structure"></moorhen-button>
    </div>
</moorhen-web-component>

Then register a modal that shows that slot, and a menu entry to open it: 

const removeModal = moorhenInstance.uiExtensions.addModal({
    id: "my-plugin",              // the modal's key, used to open and close it
    title: "My plugin",           // the modal's header
    slotName: "my-plugin-body",   // matched by slot="my-plugin-body" in your HTML
    initialWidth: 420,            // optional: initialHeight, minWidth, maxWidth, allowDocking…
    onOpen: () => console.log("opened"),
    onClose: () => console.log("closed"),
});

moorhenInstance.menuSystem?.addToExistingSubmenu(
    [{ id: "open-my-plugin", label: "My plugin", type: "showModal", modal: "my-plugin" }],
    "file"
);

document.getElementById("my-plugin-load")?.addEventListener("click", () => {
    moorhenInstance.files.loadFiles("/my-structure.pdb");
});

Moorhen draws the modal (header, dragging, resizing, docking) and puts your content in its body. You can also open and close it from code, with moorhenInstance.modals.showModal({ key: "my-plugin" }) and moorhenInstance.modals.hideModal("my-plugin"). addModal returns a function that removes the modal again.

  • Your content stays in your page while the modal is closed, so its state (a typed value, a scroll position) survives closing and reopening. onOpen / onClose tell you when it is shown.
  • Use ids and slot names that cannot clash with Moorhen’s or another plugin’s: prefix them with your plugin’s name. A modal id equal to one of Moorhen’s own replaces it.
  • Inside the web component, a modal or panel can only be a slot: the component and content options (React components) are for the moorhen/react-lib integration, and addModal throws if you use them here.

A side panel

A side panel works the same way. Moorhen adds the title bar and a tab with your icon: 

moorhenInstance.uiExtensions.addSidePanel({
    id: "my-plugin-panel",
    label: "My plugin",           // tab label, and title unless you give `title`
    icon: "MatSymAdd",
    slotName: "my-plugin-panel-body",
});

// Open it from a menu ({ type: "showPanel", panel: "my-plugin-panel" }) or from code:
moorhenInstance.globalUI.setShownSidePanel("my-plugin-panel");

A slot can only be shown in one place at a time. To offer the same tools in a modal and in a side panel, render them twice, under two slot names, as the full example below does.

2. Moorhen’s UI elements

Plain HTML works in a slot, but it is styled by your page. To give your plugin Moorhen’s look, use Moorhen’s own controls as custom elements. registerMoorhenWebComponent() defines them along with <moorhen-web-component>:

Element Value Main attributes
<moorhen-button> – (listen to click) label, icon, type (default, icon-only, toggle), variant, size, tooltip, disabled, checked
<moorhen-toggle> checked label (or the element’s text), type (switch, checkbox, radio), disabled
<moorhen-number-input> value: number or null label, min, max, decimal-digits, integer, show-buttons, step, wait-return
<moorhen-slider> value (and value2 with type="range") label, min, max, step, scale (linear, log, asinh), unit, decimal-places, hide-buttons
<moorhen-colour-picker> value: "#rrggbb" ("#rrggbbaa" with use-alpha) tooltip, position, inline, hide-swatches
<moorhen-molecule-select> value: a molecule’s unique id; values with multiple label, allow-any, multiple; property filter
<moorhen-chain-select> value: a chain id; values with multiple molecule (a unique id), label, allow-all, multiple; property allowedTypes
<moorhen-map-select> value: a map’s unique id label; property filter
<moorhen-info-card> – info (or the element’s content, which can be rich HTML), placement, large

Each element’s full list of attributes and properties is in its class documentation in the API Reference (MoorhenButtonElement, MoorhenToggleElement…).

They behave like native inputs

The elements follow the rules of <input> and <select>, so the usual DOM code works:

  • The value is in the value / checked property: read and set it from code (toggle.checked = true, select.value). The attribute of the same name gives the starting value, and sets the value again whenever it changes, which is what a framework rendering <moorhen-toggle checked={on}> needs.
  • change fires when the user has made a change: a tick, a pick, a slider released, a number committed with Enter or by leaving the field, a colour picker closed.
  • input fires while the user is still changing a value: dragging a slider, typing a number, picking a colour. Use it for live feedback.
  • Changes made by code fire no event: setting value / checked from a script, or a dropdown picking its first item by itself.
<div slot="my-plugin-body">
    <moorhen-toggle id="axes">Draw axes</moorhen-toggle>
    <moorhen-slider id="zoom" label="Zoom" min="0.05" max="5" scale="log" decimal-places="2"></moorhen-slider>
</div>
import type { MoorhenSliderElement, MoorhenToggleElement } from "moorhen/web-component";

const axes = document.getElementById("axes") as MoorhenToggleElement;
const zoom = document.getElementById("zoom") as MoorhenSliderElement;

axes.addEventListener("change", () => moorhenInstance.sceneSettings.setDrawAxes(axes.checked));
// `input`: the view zooms while the slider is dragged, not only when it is released
zoom.addEventListener("input", () => moorhenInstance.sceneSettings.setZoom(zoom.value));

How they work: each element finds the <moorhen-web-component> it is in, waits for its instance, and renders Moorhen’s own React component in its own shadow root, with that instance’s store. That is why a molecule select lists the molecules loaded in this Moorhen, and why the elements follow Moorhen’s light and dark themes. They use Moorhen’s stylesheet, already loaded by the web component, so they cost no extra download.

Outside Moorhen

The elements also work in the rest of your page, outside the web component: a Moorhen switch in your own toolbar, say. An element works with the <moorhen-web-component> it is in; outside one, with the only one in the page. With several in the page, give the id of one in its moorhen attribute: 

<div class="my-toolbar">
    <moorhen-toggle id="spin" moorhen="moorhen-1">Spin</moorhen-toggle>
</div>

Wire it as any other element. Its tooltips and cards still open next to it. Without a Moorhen to work with (none in the page, or several and no moorhen attribute), an element logs an error and renders nothing.

3. Staying in sync with Moorhen

The toggle above changes Moorhen, but it does not notice when the user turns the axes off from Moorhen’s own menu. To keep a control right whatever changes the setting, also follow Moorhen’s state, and set the element’s property when it changes: 

const state = () => moorhenInstance.store.getState();

axes.checked = state().sceneSettings.drawAxes;
const unsubscribe = moorhenInstance.subscribeToStore(
    s => s.sceneSettings.drawAxes,
    drawAxes => { axes.checked = drawAxes; }
);

Setting the property fires no event, so this cannot loop back into setDrawAxes. The same pattern keeps two copies of a control (one in the modal, one in the side panel) in agreement: both follow the store. See Callbacks and subscriptions for the store and its subscriptions; in React, section 6 does the same in two lines.

4. Picking molecules, chains and maps

The selection elements list what is loaded in Moorhen and keep up as structures and maps are loaded and deleted. Their values are unique ids, as in the rest of the API, so you can find the object in the store or pass the id on: 

<moorhen-molecule-select id="molecule" label="Molecule"></moorhen-molecule-select>
<moorhen-chain-select id="chains" for="molecule" label="Chains" multiple></moorhen-chain-select>
<moorhen-map-select id="map" label="Map"></moorhen-map-select>
  • <moorhen-chain-select for="molecule"> lists the chains of the molecule picked in the molecule select with that id, and follows it: when the user picks another molecule, and when the dropdown picks one by itself as structures are loaded. No code is needed. Without for, give the molecule’s unique id in its molecule attribute or property.
  • multiple turns a dropdown into a list of checkboxes with Check all and Uncheck all, like <select multiple>. values holds the selected ids, all of them at first; value is the first one. A chain list ticks all chains again when its molecule changes.
  • filter (a function, so a property) lists only some molecules or maps, e.g. mapSelect.filter = map => map.isDifference.

Read the selection when you need it, or listen to change. Plugins can report back inside Moorhen too, for instance with a snackbar message: 

import type { MoorhenChainSelectElement, MoorhenMoleculeSelectElement } from "moorhen/web-component";

const molecule = document.getElementById("molecule") as MoorhenMoleculeSelectElement;
const chains = document.getElementById("chains") as MoorhenChainSelectElement;

const selected = state().molecules.moleculeList.find(m => m.uniqueId === molecule.value);
moorhenInstance.snackbar.enqueueSnackbar({
    message: `${selected?.name}: chains ${chains.values.join(", ")}`,
    variant: "info",
});

5. Help with an info card

<moorhen-info-card> is Moorhen’s info button: it opens a card with help text. Short text goes in the info attribute; longer help is the element’s own content, styled like Moorhen’s info cards: 

<moorhen-info-card info="Keeps only the residues within the radius."></moorhen-info-card>

<moorhen-info-card large>
    <h1>My plugin</h1>
    <p>What it does, step by step…</p>
</moorhen-info-card>

The card opens in Moorhen’s popup layer, outside your page, so it shows a copy of the content, kept up to date when the content changes; the content itself is not shown in the page. It is meant for static help: buttons or inputs in it would not be wired up.

6. In React

Everything above works in React too, but moorhen/web-component/react makes it read like React: a component for each of Moorhen’s UI elements, with React props and callbacks that receive the new value, and hooks to find Moorhen and follow its state. It uses your app’s own React (any version from 18; it does not need to match Moorhen’s) and adds a few kilobytes.

Export What it does
MoorhenButton, MoorhenToggle, MoorhenSlider, MoorhenNumberInput, MoorhenColourPicker, MoorhenMoleculeSelect, MoorhenChainSelect, MoorhenMapSelect, MoorhenInfoCard Render the elements. Props in camelCase (decimalPlaces, allowAny); onChange / onInput receive the new value (checked, value, or the list of values with multiple); a ref is the element.
useMoorhenInstance(target) The MoorhenInstance, once ready (null until then). target is the web component’s element id, or a ref to an element inside it, such as your slotted content: a plugin then needs no id.
useMoorhenSelector(target, selector) A value of Moorhen’s state, kept up to date: the component re-renders when it changes.

A plugin is then a component that the app renders inside the web component: 

<moorhen-web-component id="my-moorhen" width={1000} height={800}>
    <ExamplePlugin />
</moorhen-web-component>

It registers its modal and menu entry, and renders the modal’s content in the slot. Its controls show Moorhen’s state and change it: 

import { useEffect, useRef } from "react";
import {
    MoorhenChainSelect,
    MoorhenMoleculeSelect,
    MoorhenToggle,
    useMoorhenInstance,
    useMoorhenSelector,
} from "moorhen/web-component/react";

export function ExamplePlugin() {
    const ref = useRef<HTMLDivElement>(null);
    const instance = useMoorhenInstance(ref);

    useEffect(() => {
        if (!instance) return;
        const removeModal = instance.uiExtensions.addModal({ id: "example-plugin", title: "Example plugin", slotName: "example-plugin" });
        const removeMenu = instance.menuSystem?.addMainMenu({ type: "modal", label: "Plugin", icon: "MatSymAdd", modal: "example-plugin" });
        return () => { removeModal(); removeMenu?.(); };
    }, [instance]);

    const drawAxes = useMoorhenSelector(ref, state => state.sceneSettings.drawAxes);

    return (
        <div slot="example-plugin" ref={ref}>
            <MoorhenToggle checked={drawAxes ?? false} onChange={checked => instance?.sceneSettings.setDrawAxes(checked)}>
                Draw axes
            </MoorhenToggle>
            <MoorhenMoleculeSelect id="example-molecule" label="Molecule" />
            <MoorhenChainSelect for="example-molecule" multiple label="Chains" />
        </div>
    );
}
  • Clean up in the effect’s return. addModal, addSidePanel and addMainMenu each return a function that removes what they added; submenu items go with deleteItemById. This also covers React’s StrictMode, which runs effects twice in development.
  • A value prop is applied when it changes, so a re-render does not undo the user’s own change. To read the current selection at any time (also a select’s own first pick, which calls no onChange), keep a ref and read .value / .values.
  • The custom elements also work in JSX directly: with React 19, onChange and onInput receive their events. React 18 does not pass those to custom elements; there, use the components above, or listen through a ref with useMoorhenEvent.

7. Loading a plugin only when it is first opened

A plugin can be heavy: a large component tree, a library of its own, data to fetch. Register its menu and modal straight away, so that they are there to be opened, but render the tools only on the first onOpen, and load their code then with React.lazy: 

import { Suspense, lazy, useEffect, useRef, useState } from "react";
import { useMoorhenInstance } from "moorhen/web-component/react";

// A separate chunk, downloaded on first use only
const PluginTools = lazy(() => import("./tools"));

export function ExamplePlugin() {
    const ref = useRef<HTMLDivElement>(null);
    const instance = useMoorhenInstance(ref);
    const [opened, setOpened] = useState(false);

    useEffect(() => {
        if (!instance) return;
        const removeModal = instance.uiExtensions.addModal({
            id: "example-plugin",
            title: "Example plugin",
            slotName: "example-plugin",
            onOpen: () => setOpened(true),
        });
        const removeMenu = instance.menuSystem?.addMainMenu({ type: "modal", label: "Plugin", icon: "MatSymAdd", modal: "example-plugin" });
        return () => { removeModal(); removeMenu?.(); };
    }, [instance]);

    return (
        <div slot="example-plugin" ref={ref}>
            {opened ? (
                <Suspense fallback={<p>Loading…</p>}>
                    <PluginTools />
                </Suspense>
            ) : null}
        </div>
    );
}
  • Before the first open, the plugin costs one small component and its menu entry. Its tools are neither downloaded nor mounted.
  • opened never goes back to false: once loaded, the tools stay mounted, so their state survives closing and reopening.
  • PluginTools finds Moorhen itself, with useMoorhenInstance on a ref of its own: it needs no props.
  • Moorhen grows a slot modal to fit content that arrives after it opened (the loading text, then the tools), up to the size of the view. Once the user resizes or docks the modal, its size is theirs.
  • Without React, the same works with onOpen and a dynamic import() of the module that builds the content.

Complete example: the React demo MoorhenWebComponentReact has this plugin in src/plugin/: index.tsx adds the Plugin menu entry and the modal, and loads tools.tsx on first open. The tools load a structure, show and change the axes and zoom, pick a molecule and its chains, and report them to the snackbar. The app’s App.tsx only renders <ExamplePlugin /> inside the web component.

Styling your content

  • Slotted content is part of your page: your CSS styles it, Moorhen’s does not. Moorhen’s UI elements are the exception: they bring Moorhen’s styles with them.
  • Moorhen’s theme colours are CSS variables (--moorhen-primary, --moorhen-background, --moorhen-border…) that reach slotted content and follow the light and dark themes. Use them to match Moorhen: color: var(--moorhen-primary).
  • Text without its own colour inherits Moorhen’s, so it also follows the dark theme.

Current limitations

  • A slot modal grows to fit its content, but does not shrink when the content does.
  • Inside the web component, modals and side panels can only be slots (see section 1).
  • A molecule dropdown’s automatic first pick fires no event: read value rather than waiting for change. (A chain select with for follows it anyway.)
  • Inputs inside the elements are in their shadow roots, so they do not take part in a <form> of your page: read the elements’ values instead.

See MoorhenUiExtensions and the element classes in the API Reference.
