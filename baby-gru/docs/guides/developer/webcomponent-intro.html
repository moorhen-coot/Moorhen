Moorhen as an embeddable Web Component

Moorhen is a web browser molecular graphics program. The moorhen npm package also ships it as a standards-based Web Component: a custom element, <moorhen-web-component>, that you can drop into any web page and then control from your own JavaScript. The whole Moorhen user interface is bundled inside the element: the OpenGL/WebGL viewport, the menu bar, panels and tools. Embedding it is therefore very close to embedding a plain <iframe>-like widget, except that you get a rich, typed API to drive it.

Technical note: the element is framework-agnostic. It is built on React internally, but your host page does not need React at all. This makes it the recommended way to embed Moorhen in a "standard" web page or application. Because the element renders into a shadow root, CSS from your page does not leak into Moorhen (and vice-versa).

Before you start: serve the Moorhen assets

At runtime the element loads its stylesheet and the WebAssembly binaries from a MoorhenAssets folder. You must copy that folder from the installed package into the static files of your project, and redo the copy after every Moorhen update. See Setting up the WebComponent for the exact steps.

The architecture of the moorhen package

The public API of the package is split across several sub-path exports. There is no bare import ... from "moorhen" entry point. Always import from a sub-path:

Module What it gives you Use it when…
moorhen/web-component The custom element (MoorhenWebComponent) and its registrar (registerMoorhenWebComponent), plus the types you need as an integrator (MoorhenWebComponentAttributes, MoorhenInstance, RootState, menu & load-result types). Embedding Moorhen in any page or application, no matter the framework (this is the recommended, easiest path for standard use).
moorhen/web-component/utils Two React hooks that wrap a mounted element: useWebComponentInstanceRef and useMoorhenSelector. You embed the element inside a React application and want the instance and store state as React primitives.
moorhen/react-lib Moorhen's own React components and hooks (MoorhenProvider, MoorhenContainer, MoorhenApp, …). The two WebComponent hooks appear in its type exports only for type-generation. They are not a supported way to drive an element from here. Import them from moorhen/web-component/utils instead. You want to embed & compose Moorhen's UI directly inside a React application (rather than using the ready-made element). More advanced; for most standard uses the web component is simpler.

See the API Reference for the full, generated documentation of each surface. The guides that follow show these imports in context.

How the WebComponent works

Using the component is a two-step process: register the custom element, then wait for it to become ready before driving it.

  1. Call registerMoorhenWebComponent() once to define the <moorhen-web-component> element.
  2. Put the element in your page with a unique id, then wait for readiness. You can watch the boolean ready property, listen for the moorhenReady event on window, or simply await element.getMoorhenInstance().

Once ready, everything is exposed on the MoorhenInstance returned by getMoorhenInstance(): loading molecules and maps, representations, the camera and the store. The DOM element itself only knows its size and attributes.

Under the hood: when connected, the element opens a shadow root, loads <url-prefix>/moorhen.css, renders the Moorhen UI inside it, and links the live MoorhenInstance back to the element via its webComponent property.
