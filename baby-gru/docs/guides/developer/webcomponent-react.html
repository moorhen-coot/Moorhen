Embedding Moorhen in a React application

The <moorhen-web-component> element is framework-agnostic, and moorhen/web-component/react gives it a React face: a <Moorhen> component with ordinary props, and hooks to reach its MoorhenInstance and follow its state. Moorhen runs on its own React inside the element, so your app’s React version does not need to match Moorhen’s.

Which integration path? The WebComponent is the preferred and easiest option for the standard use case: embedding the whole Moorhen UI in your page, including inside React apps. The alternative, moorhen/react-lib (Moorhen’s own React components such as MoorhenProvider / MoorhenContainer), lets you compose the UI directly in React and is discussed at the end of this guide.

1. Prerequisites

Do the setup from Setting up the WebComponent first. In short, your React app must:

  • install moorhen and copy MoorhenAssets into its static folder (public/ in a Vite app);
  • serve the page cross-origin isolated, with the Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy headers, or Moorhen’s WebAssembly threads cannot start.

The setup guide has the exact commands, the header values, and ready-made Vite, nginx and Python server configurations.

2. The <Moorhen> component

Register the web component once, then render <Moorhen>: 

import { registerMoorhenWebComponent } from "moorhen/web-component";
import { Moorhen } from "moorhen/web-component/react";

registerMoorhenWebComponent();

function App() {
    return <Moorhen id="my-moorhen" width={1000} height={800} />;
}
Prop What it does
width, height A fixed size, following your state. Leave them out and Moorhen fills its container, usually what you want in a responsive layout (see Sizing the element).
urlPrefix, viewOnly, disableFileUploads As the element’s attributes, and can change at any time.
monomerLibraryPath, allowScripting, backupStorage Start-up settings: read when Moorhen starts.
onReady Called once Moorhen is ready, with its MoorhenInstance.
id, className, style, ref As for any element; a ref is the <moorhen-web-component> element.
children Placed inside the element: plugins and content for Moorhen’s slots (see Writing a plugin).

3. Getting the instance and reading the store

onReady hands you the MoorhenInstance; keep it in state. To show part of Moorhen’s state, useMoorhenSelector returns it and re-renders your component when it changes, the React equivalent of instance.subscribeToStore(...): 

import { useState } from "react";
import type { MoorhenInstance } from "moorhen/web-component";
import { Moorhen, useMoorhenSelector } from "moorhen/web-component/react";

function MyMoorhen() {
    const [instance, setInstance] = useState<MoorhenInstance | null>(null);
    const molecules = useMoorhenSelector("my-moorhen", state => state.molecules.moleculeList);

    return (
        <div>
            <p>Ready: {instance ? "yes" : "no"}, molecules loaded: {molecules?.length}</p>
            <Moorhen id="my-moorhen" onReady={setInstance} />
        </div>
    );
}

useMoorhenInstance("my-moorhen") gives the instance anywhere else in your app. Both hooks take the element’s id, or a ref to an element inside it (see Writing a plugin).

4. Controlling Moorhen from React state

The size follows your state through the props. For everything else, call the instance, in an effect when it follows your state: 

function MyMoorhen() {
    const [instance, setInstance] = useState<MoorhenInstance | null>(null);
    const [width, setWidth] = useState(1000);
    const [background, setBackground] = useState<[number, number, number]>([0.85, 0.9, 1.0]);

    useEffect(() => {
        instance?.sceneSettings.setBackgroundColor([...background, 1]);
    }, [instance, background]);

    return (
        <div>
            <label>Width <input type="number" value={width} onChange={e => setWidth(Number(e.target.value))} /></label>
            <button onClick={() => instance?.files.loadFiles("/my-structure.pdb")}>Load</button>
            <Moorhen id="my-moorhen" width={width} height={800} onReady={setInstance} />
        </div>
    );
}

Everything from the MoorhenInstance API page is available on the instance. The same pattern works for your app’s theme: hold the light/dark choice in React state and let an effect push the matching background colour into Moorhen. See Matching your page theme.

Full API: loading data, representations, scene settings and the other instance groups are identical to the plain-page case. See Loading data and the MoorhenInstance API.

5. The element itself

<Moorhen> renders <moorhen-web-component>, which you can also use in JSX directly. TypeScript then needs the tag declared once, mapped to the exported MoorhenWebComponentAttributes type: 

import { MoorhenWebComponentAttributes } from "moorhen/web-component";

declare module "react" {
    namespace JSX {
        interface IntrinsicElements {
            "moorhen-web-component": MoorhenWebComponentAttributes;
        }
    }
}

Its attributes are dashed (url-prefix, view-only…), booleans are given as "true" / "false", and the instance comes from useMoorhenInstance("my-moorhen"). The older hooks of moorhen/web-component/utils (useWebComponentInstanceRef, useMoorhenSelector) still work.

Note: these hooks drive a mounted <moorhen-web-component> element, so import them from moorhen/web-component/react (or /utils). Although they also appear among moorhen/react-lib’s type exports (for type-generation purposes), importing them from react-lib is not supported: the moorhen/react-lib embedding path (MoorhenProvider/MoorhenContainer) does not mount a <moorhen-web-component> element for them to find.

The moorhen/react-lib alternative

The ready-made element does not fit every need. For example, you may want to embed individual Moorhen panels or remix its UI. In that case you can build against moorhen/react-lib, which exposes Moorhen’s own React components (MoorhenProvider, MoorhenContainer, MoorhenApp, …). That path requires React as a peer dependency and a deeper understanding of Moorhen’s internals, so we recommend it only for advanced, UI-heavy integrations.

For standard use, stick with the WebComponent pattern shown in this guide (or in the plain-page setup guide). It is the simplest and most robust option for putting Moorhen on your page and driving it with your own code.

A complete, runnable React example is in the example project MoorhenWebComponentReact.
