Embedding Moorhen in a React application

The <moorhen-web-component> element is framework-agnostic, so you can use it inside a React application just like any other element. This guide shows the recommended pattern for React hosts. It uses two helper hooks, useWebComponentInstanceRef and useMoorhenSelector, to bridge the element’s world (a DOM node exposing a MoorhenInstance) with React’s world (refs, state and effects).

Which integration path? The WebComponent is the preferred and easiest option for the standard use case: embedding the whole Moorhen UI in your page, including inside React apps. The alternative, moorhen/react-lib (Moorhen’s own React components such as MoorhenProvider / MoorhenContainer), lets you compose the UI directly in React and is discussed at the end of this guide.

1. Prerequisites

Install the package and copy the Moorhen assets into your app’s static folder (a Vite/React app serves public/ at the root):

npm install moorhen
cp -r node_modules/moorhen/public/MoorhenAssets public/

This is exactly the same step as in the plain-page guide. See Setting up the WebComponent for details. A Vite plugin that automates the copy is planned but not usable yet.

2. Typing the custom element in JSX

TypeScript does not know the <moorhen-web-component> tag. Declare it once in your project (in any module that has an import/export) by mapping the tag to the exported MoorhenWebComponentAttributes type: 

import { MoorhenWebComponentAttributes } from "moorhen/web-component";

declare module "react" {
    // eslint-disable-next-line @typescript-eslint/no-namespace
    namespace JSX {
        interface IntrinsicElements {
            "moorhen-web-component": MoorhenWebComponentAttributes;
        }
    }
}

MoorhenWebComponentAttributes is a type (it is elided at runtime) describing the accepted props: width, height, url-prefix, disable-file-uploads and view-only, plus the usual React HTML attributes. It is documented on the MoorhenWebComponent API page.

3. Rendering the element

Put a single <moorhen-web-component> in your JSX with a unique id. The two hooks below target the element by that id, so pick one and keep it consistent: 

<moorhen-web-component id="my-moorhen" width={1000} height={800} view-only={false} />

4. Getting the instance and reading the store

Import the hooks from moorhen/web-component/utils:

  • useWebComponentInstanceRef(elementId) returns [isReady, instanceRef]. It polls the element until its MoorhenInstance is ready, stores it in instanceRef and re-renders your component once ready.

  • useMoorhenSelector(elementId, selector) subscribes to Moorhen’s Redux store and returns the value selected by selector (or null until ready). This is the React-friendly equivalent of instance.subscribeToStore(...).

import { useMoorhenSelector, useWebComponentInstanceRef } from "moorhen/web-component/utils";

function MyMoorhen() {
    const [isReady, moorhenInstanceRef] = useWebComponentInstanceRef("my-moorhen");
    const openedMolecules = useMoorhenSelector(
        "my-moorhen",
        (state) => state.molecules.moleculeList,
    );

    return (
        <div>
            <p>Ready: {isReady ? "yes" : "no"} - molecules loaded: {openedMolecules?.length}</p>
            <moorhen-web-component id="my-moorhen" />
        </div>
    );
}

Because the selector result is live, the openedMolecules count updates automatically whenever a molecule is added or removed. This is exactly like calling subscribeToStore manually, but without the bookkeeping.

Note: these hooks are written to drive a mounted <moorhen-web-component> element, so always import them from moorhen/web-component/utils. Although the hooks also appear among moorhen/react-lib's type exports (for type-generation purposes), importing them from react-lib is not a supported way to drive the element. The moorhen/react-lib embedding path (MoorhenProvider/MoorhenContainer) does not mount a <moorhen-web-component> element for them to find.

5. Controlling Moorhen from React state

The element and its instance are external objects. They are not React-managed. To push React state into Moorhen you assign to the ref (which forwards to the element) inside an effect. The example below keeps the size in React state and syncs it to the element, and sets the background colour once the instance exists: 

import { useEffect, useState } from "react";

function MyMoorhen() {
    const [_, moorhenInstanceRef] = useWebComponentInstanceRef("my-moorhen");
    const [width, setWidth] = useState(1000);
    const [height, setHeight] = useState(800);

    // Push size changes into the (external) element.
    useEffect(() => {
        if (moorhenInstanceRef.current) {
            moorhenInstanceRef.current.width = width;
            moorhenInstanceRef.current.height = height;
        }
    }, [width, height, moorhenInstanceRef]);

    // Configure the scene once the instance is available.
    useEffect(() => {
        if (moorhenInstanceRef.current) {
            moorhenInstanceRef.current.sceneSettings.setBackgroundColor([0.85, 0.9, 1.0, 255]);
        }
    }, [moorhenInstanceRef]);

    return (
        <div>
            <label>Width <input type="number" value={width}
                onChange={(e) => setWidth(Number(e.target.value))} /></label>
            <label>Height <input type="number" value={height}
                onChange={(e) => setHeight(Number(e.target.value))} /></label>
            <moorhen-web-component id="my-moorhen" width={width} height={height} />
        </div>
    );
}

The instance also forwards viewOnly, urlPrefix and disableFileUploads, and exposes the whole driveable API. For example, load files with moorhenInstanceRef.current.files.loadFiles([...]) or centre the view with centerOnResidue(...). Once your component has the ref, everything from the MoorhenInstance API page is available.

The moorhen/react-lib alternative

The ready-made element does not fit every need. For example, you may want to embed individual Moorhen panels or remix its UI. In that case you can build against moorhen/react-lib, which exposes Moorhen’s own React components (MoorhenProvider, MoorhenContainer, MoorhenApp, …). That path requires React as a peer dependency and a deeper understanding of Moorhen’s internals, so we recommend it only for advanced, UI-heavy integrations.

For standard use, stick with the WebComponent pattern shown in this guide (or in the plain-page setup guide). It is the simplest and most robust option for putting Moorhen on your page and driving it with your own code.
