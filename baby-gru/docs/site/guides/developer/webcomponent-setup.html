Embedding the WebComponent in a plain page

This guide walks through a minimal, runnable integration of the Moorhen WebComponent in a host page written in plain TypeScript/JavaScript. It covers the three things you need to get started: serving the Moorhen assets, registering the element and waiting until it is ready, and then loading a structure and controlling the view.

Prerequisite: you should be comfortable with the concepts and the module layout described in The Moorhen WebComponent. In particular we import everything from the moorhen/web-component sub-path. There is no bare moorhen import.

1. Install the package and copy the Moorhen assets

Install moorhen in your project:

npm install moorhen

The element needs static assets (styles, icons and WebAssembly binaries) at runtime. Copy them from the installed package into the public/ folder of your own project, so they are served from /MoorhenAssets/...: 

cp -r node_modules/moorhen/public/MoorhenAssets public/

Important: copy the assets again after every Moorhen update, because the WebAssembly binaries inside MoorhenAssets can change in any version.

A Vite plugin that automates this copy is planned but not usable yet. Copy the assets manually for now. If you serve them from a different path, set the url-prefix attribute on the element (see Element attributes below).

Technical note: because Moorhen loads WebAssembly modules and uses web workers, you must serve the page over HTTP(S) (e.g. a Vite dev server, or python3 -m http.server) rather than opening the file directly from disk.

2. The host HTML page

Start from a very small page. The important parts are the <moorhen-web-component> element (give it a unique id and a size) and a module script that imports your entry point: 

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>My Moorhen page</title>
  </head>
  <body>
    <h1>Moorhen</h1>

    <p id="loading-text">No structure loaded yet.</p>

    <moorhen-web-component id="moorhen-1" width="1000" height="800"></moorhen-web-component>

    <button id="load-7avk">Load 7AVK (PDBe)</button>
    <button id="center-residue-1231">Centre on residue 1231</button>

    <script type="module" src="./main.ts"></script>
  </body>
</html>

The buttons and the paragraph are plain HTML hooks. Your code will wire them up to the Moorhen API. In the rest of this guide, main.ts is your module entry point (transpile it to JavaScript for production, as you would with any TypeScript project).

3. Register the element and obtain the instance

First, register the custom element and grab a strongly-typed reference to it. Then wait for Moorhen to be ready with getMoorhenInstance(), which resolves to the MoorhenInstance you will use for everything else: 

import { registerMoorhenWebComponent, MoorhenWebComponent } from "moorhen/web-component";

// Define the <moorhen-web-component> custom element (idempotent).
registerMoorhenWebComponent();

// A typed handle on the element we put in the HTML above.
const moorhen = document.getElementById("moorhen-1") as MoorhenWebComponent;

// Resolves once Moorhen has finished mounting (wasm downloaded, scene built).
const moorhenInstance = await moorhen.getMoorhenInstance();

getMoorhenInstance() resolves immediately if the element is already ready, otherwise it waits until it is. The same readiness is also exposed as the boolean property element.ready, and a moorhenReady CustomEvent is dispatched on window (its detail.id is the element id). See the MoorhenWebComponent API page. Because we call it at the top level of a module, await is fine here.

4. Loading a structure and maps from URLs

Molecules and maps are loaded through moorhenInstance.files.loadFiles(). It accepts one or more URLs (or Files, strings, URLs…) and returns a result per file telling you what was loaded and how to refer to it: 

interface LoadFilesResult {
    type: "molecule" | "map";
    uniqueID: string;   // use this to refer to the molecule/map later
    molNo: number;
    fileName: string;
}

The example below fetches the structure and the two maps of the PDB entry 7AVK straight from PDBe and returns the load results so the caller can pick out the molecule’s uniqueID: 

import type { LoadFilesResult } from "moorhen/web-component";

const PDBe_FILES = "https://www.ebi.ac.uk/pdbe/entry-files";

async function loadEntryFromPDBe(entryId: string): Promise<LoadFilesResult[]> {
    const results = await moorhenInstance.files.loadFiles([
        `${PDBe_FILES}/${entryId}.cif`,             // coordinates
        `${PDBe_FILES}/${entryId}.ccp4`,            // 2Fo-Fc map
        `${PDBe_FILES}/${entryId}_diff.ccp4`,       // difference map
    ]);
    return results;
}

Wire it up to the Load button, remembering the uniqueID of the molecule that was created: 

let proteinUniqueId: string | null = null;

document.getElementById("load-7avk")?.addEventListener("click", async () => {
    const results = await loadEntryFromPDBe("7avk");
    proteinUniqueId =
        results.find((item) => item.type === "molecule" && item.fileName.endsWith(".cif"))?.uniqueID ?? null;

    const loadingText = document.getElementById("loading-text");
    if (loadingText) {
        loadingText.textContent = `Structure ${proteinUniqueId ?? "?"} loaded.`;
    }
});

Keep the molecule’s uniqueID around: it is the stable handle you pass to most other API calls (centring, representations, validation, …). You can also ask the instance for the loaded molecules at any time with moorhenInstance.getMoleculeList() (or getMolecule(uniqueID)).

5. Controlling the view

Once a structure is loaded you can drive the camera. To centre on a specific residue, use centerOnResidue(chain, residueNumber, moleculeUniqueId): 

document.getElementById("center-residue-1231")?.addEventListener("click", () => {
    if (proteinUniqueId) {
        moorhenInstance.centerOnResidue("A", 1231, proteinUniqueId);
    }
});

Scene-wide settings live under moorhenInstance.sceneSettings. These include background colour, ambient light, axes and perspective. For example, to set a light blue background (RGB values from 0 to 1, alpha 255): 

moorhenInstance.sceneSettings.setBackgroundColor([0.85, 0.9, 1.0, 255]);

API tip: centerOnResidue, centerOnAtom and centerOnCoordinate are methods of MoorhenInstance, while the generated sceneSettings setters (a large family including setBackgroundColor, setAmbient, setZoom …) are described on the same API page.

6. Element attributes

The custom element accepts a few HTML attributes that change how it is set up:

Attribute Property Purpose
width / height width / height Size of the element, e.g. "1000" / "800".
url-prefix urlPrefix Base path of the Moorhen assets (default "MoorhenAssets"). Set it if you did not copy the assets to public/MoorhenAssets.
view-only viewOnly Set to "true" to hide editing features and expose a view-only UI.
disable-file-uploads disableFileUploads Set to "true" to prevent the user from loading files through the UI.

For example, a view-only element whose assets live under a custom prefix:

<moorhen-web-component
    id="moorhen-2"
    width="900"
    height="700"
    url-prefix="/static/MoorhenAssets"
    view-only="true">
</moorhen-web-component>
